      Latency is one-way publish→receive over a … link emulated in-process for both transports (same RTT, same bottleneck, same queue model). Server and browser share this machine's clock, so the timestamps are directly comparable. The WebSocket pane is a lean binary-envelope implementation, not a strawman — its handicap is structural: one TCP stream is one FIFO queue, so a 70 KB screen frame ahead of a 10-byte token delays the token. quicrtc carries each lane on its own QUIC stream (screen: stream-per-GOP · tokens: low-latency stream · tool calls: bidi-per-call · telemetry: datagrams), so they only share bandwidth, never a queue. Headless version of this comparison: go run ./examples/agent-desktop -bench 30s.
