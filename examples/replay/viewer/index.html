Why quicrtc
All four lanes ride one QUIC connection on one capture clock, so this frame-aligned replay is exact and essentially free. Reconstruct the same view from a glued WebRTC + SSE + gRPC + OTLP stack and you're correlating four clocks across four connections.
Try it
Flip the toggle to glued stack · 4 clocks: replayed as four independent connections, each lane arrives later by its own latency (illustrative) — the dots slide right by different amounts, the lanes drift apart, and the slowest lane drags the session's end past where quicrtc finished. You can no longer say what the agent saw at the instant it clicked. quicrtc's single connection + clock keeps every lane frame-exact and the session shortest. This page shows the observability payoff.
