Latency is one-way publish→receive over one emulated … link per arm (same RTT, same bottleneck, same queue model; within the glued arm its three connections share one link). All three arms run the identical latest-frame-wins screen protocol — the WS arms via an ack message, quicrtc via a publish-back receipts track — so the screen lane is a controlled variable and the interactive lanes are the experiment. The baselines are steelmanned: lean binary envelopes, ack-paced frames, and hand-rolled SSE token replay on the glued arm. The network-drop button closes every arm's connection(s), waits 1.5 s, and reconnects: quicrtc re-dials once with {session, last_seen} and the server replays what was missed; the glued arm re-opens three connections and recovers only its SSE lane; the single WS recovers nothing. Headless version: go run ./examples/agent-desktop -bench 60s.
