# integration_test

End-to-end tests that drive quicrtc over **real QUIC + WebTransport on
loopback**. They exist to catch wire-protocol and handshake regressions
that compile-pass but runtime-fail once packets actually traverse the
stack — the kind of bugs unit tests in `wire/`, `session/`, and
`feed/` won't catch on their own.

Unit tests verify each component in isolation against fakes. Benchmarks
in [`../benchmarks/`](../benchmarks/) measure performance against
incumbents. This package verifies that the components talk to each
other correctly when wired up over the real transport.

## What's covered

### `e2e_test.go` — low-level client/server API

Drives `client.Client` against `server.Server` directly (the pre-PC
API still used by the relay and by lower-level callers).

| Test | What it asserts |
|---|---|
| `TestEndToEndPublishSubscribe` | Publisher → subscriber AU flow; SDP negotiated via HELLO; keyframe-first ordering |
| `TestEndToEndDataChannel` | Bidirectional `datachannel.Channel` send/recv over a real bidi QUIC stream |
| `TestEndToEndAuthRejection` | A wrong slug fails the HELLO handshake — auth runs before stream setup |
| `TestEndToEndShareLinkParsing` | `sharelink.Parse` round-trips `server.ShareLink()` end-to-end |
| `TestEndToEndConcurrentSubscribers` | N subscribers on one publisher all receive the AU stream |

### `pc_e2e_test.go` — unified `PeerConnection` API

Drives the Phase 1 `peerconnection.PeerConnection` (the public surface
most users build against).

| Test | What it asserts |
|---|---|
| `TestPCPublishSubscribe` | PC-level publish/subscribe; `RemoteTrack` populated after `Connect` |
| `TestPCDataChannel` | DC roundtrip through the PC API; server-side `OnDataChannel` fires |
| `TestAuthValidatorRejects` | Custom `AuthValidator` returning an error blocks Connect, slug match notwithstanding |
| `TestAuthValidatorAccepts` | Custom `AuthValidator` ignoring the slug accepts (bearer-token shape) |
| `TestCapabilityNegotiation` | Capability bits flow through HELLO and surface on both sides |
| `TestBackpressureSignaling` | Backpressure signals propagate from subscriber to publisher via the wire |
| `TestServerGracefulShutdown` | `Close()` drains in-flight streams cleanly; no panic on cancelled context |
| `TestPCDynamicTrackAddRemove` | Tracks added/removed after Connect are reflected on the remote side |
| `TestPCPublishBack` | Subscriber-initiated publish-back stream (bidi roles) |
| `TestPCConcurrentSubscribers` | Multiple subscribers on one PC publisher, all receive |

## Running them

```bash
# Whole suite
go test -v ./testing/integration_test/...

# One test
go test -v -run TestPCDataChannel ./testing/integration_test/

# With the race detector — recommended for any change touching
# session/, feed/, or transport wiring
go test -race ./testing/integration_test/ -count=1
```

CI runs the suite on every push; see
[`../../.github/workflows/test.yml`](../../.github/workflows/test.yml).

## Conventions

- **Loopback only.** Tests bind `127.0.0.1:0` and use a self-signed
  cert generated by `cert.Generate`. No external network, no fixtures
  on disk. Reproducible on any dev machine.
- **`t.Cleanup` for teardown.** Each helper (`startServer`,
  `dialClient`, `startPCPublisher`, `dialPCSubscriber`) registers its
  own cleanup; tests don't manually close servers or clients.
- **Short timeouts.** Operations use 2–5 s deadlines so a hung test
  fails fast rather than blocking CI. If a test legitimately needs
  longer, raise the per-operation timeout, not the test timeout.
- **No mocks of the transport.** Anything that can be tested with a
  fake transport belongs in `session/` or `transport/` unit tests, not
  here. The point of this package is that the real QUIC stack is in
  the loop.

## When to add a test here

Add an integration test when:

- A change touches the **wire format** (`wire/`), the **HELLO
  handshake**, or the **session-establishment path**.
- A new `PeerConnection` config option needs to be verified end-to-end
  (e.g., a new auth shape, a new capability bit).
- A bug reproduced only when packets actually crossed the QUIC stack —
  unit tests with fakes missed it.

Don't add a test here for behavior already covered by a unit test
against a fake transport; it's slower and the signal is the same.
